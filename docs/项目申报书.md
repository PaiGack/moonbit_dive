# dive 项目申报书

**基本信息**
- 项目名称：dive：OCI 镜像体检与体积门禁的 MoonBit 工具集
- 参赛者：Pai2s
- 联系方式：GitHub @PaiGack
- GitHub 仓库链接：https://github.com/PaiGack/moonbit_dive
- 项目方向：MoonBit 系统工具 / 容器镜像基础设施 / CI 工程化
- 是否为移植项目：是，参考 [wagoodman/dive](https://github.com/wagoodman/dive)（Go，MIT，约 11.5k 行）

**项目简介**

dive 把「容器镜像里装了什么、哪里胖、哪里白写了」搬到 MoonBit 生态：解析 OCI 镜像、把 tar 层叠成文件树、
按层核算体积、给出 efficiency 分数，并把结论变成 CI 里能拦住的退出码。
面向在 MoonBit 里做镜像构建工具、CI 平台、制品治理与教学演示的开发者，提供能把「镜像解析 → 层叠语义 → 体积账 → 门禁判定」
串起来的可复用库：离线分析链 `oci_spec` → `layer_tree` → `image_analysis` → `image_ci` 单向分层，
外侧挂 `docker_cli`（本地 daemon）、`registry_cli`（直连 registry）、`tui`（终端交互）

**核心功能范围**
- `oci_spec`：OCI image-spec 类型层，manifest / index / config / descriptor / platform、digest 解析与校验、media type 常量
- `layer_tree`：流式 tar 叠成文件树、`.wh.` / `.wh..wh..plnk` whiteout 语义、层间 diff（`modified` 按 (kind, mode, uid, gid) + 内容指纹判等）、路径规范化、树渲染、逐层浏览 `browse_layers`
- `image_analysis`：逐层体积核算、跨层重复写入、被删浪费、efficiency score、热点路径，输出 text / JSON / HTML 报告，同时给 dive 的 `inefficientBytes` 与 `userWastedPercent` 口径
- `image_ci`：门禁规则 DSL，`maxImageSize` / `maxLayerSize` / `maxWastedSize` / `minEfficiency` / `maxFileSize` / `denyPaths` / `allowPaths`，从 JSON 加载，退出码 0/1/2，CI 注解输出
- `docker_cli`：镜像获取，docker/podman/nerdctl CLI 后端 + unix socket Engine 后端，探测降级、超时
- `registry_cli`：自己当 registry 客户端，`token → manifest（按平台选 index）→ blobs` 拉镜像，落 docker-archive tar 或 OCI layout，全程不碰 daemon；
- `tui`：全屏交互式看树（alternate screen、分栏、键鼠、帮助浮层），键位逐条对齐原版 dive
- `cmd/main`：总 CLI，位置参数自己判别（stdin / 本地归档 / 镜像引用）/ `--rules` / `--format text|json|html|annotations` / `--layer` / `--path` / `--efficiency` / `--tui` / `--save` / `--no-pull`（`--efficiency` 配 `--top` 限条数）
- 工程设施：`scripts/ci.sh` 统一驱动 GitHub Actions 与 CNB，覆盖 `moon fmt --check`、`moon info` 后 `.mbti` 一致性断言、`moon test --deny-warn --enable-coverage`、native 构建、CLI 冒烟

**移植或参考说明**
- 原项目名称：dive（wagoodman/dive）
- 原项目链接：https://github.com/wagoodman/dive
- 原项目许可证：MIT
- 本项目许可证：Apache-2.0

与原项目相比，本项目做了以下重新设计：

- 定位为库优先：原版是一体化 TUI 应用，本项目把镜像解析、层叠树、体积分析、门禁拆成可独立复用的 MoonBit 包，TUI 只是其中一层视图
- 不移植 docker/cli、docker/docker、gocui 等 Go 生态依赖：镜像获取改为进程内封装 CLI 后端 + 直连 unix socket 的 Engine 后端，另加原版没有的 registry 直连拉取
- 门禁在原版四个阈值规则之外补齐路径白/黑名单与单文件上限，规则以 MoonBit 数据结构表达、从 JSON 加载
- 口径差异（`wasted` 的两种算法、efficiency 分母是否剔除 base image）逐条写进文档，JSON 报告同时给出两套字段便于与原版对照；
- tar、gzip/zstd、sha256、JSON 复用 `moonbitlang/x`、`moonbitlang/async`，只自研 whiteout 语义、层叠 diff、efficiency 口径、规则 DSL、终端宽度表
- 术语沿用原版（`inefficientBytes` / `userWastedPercent` / whiteout），代码与文档均标注来源，不复制原版源码
