**基本信息**

- 项目名称：dive：OCI 镜像体检与体积门禁的 MoonBit 工具集
- 参赛者：Pai2s
- 联系方式：GitHub @PaiGack
- GitHub 仓库链接：https://github.com/PaiGack/moonbit_dive
- MoonBit 模块：`PaiGack/dive`（已发布 mooncakes.io，v0.1.1）

- 是否为移植项目：是，参考 [wagoodman/dive](https://github.com/wagoodman/dive)（Go，MIT）的技术核心，非逐行移植

## 项目简介

dive 把「容器镜像里到底装了什么、哪里胖、哪里白写了」这件事搬到 MoonBit 生态：
解析 OCI 镜像、把 tar 层叠成文件树、按层核算体积、给出 efficiency 分数，并把结论变成 CI 里能拦住的退出码。

面向在 MoonBit 里做镜像构建工具、CI 平台、制品治理与教学演示的开发者：
他们需要的不只是一个界面，而是能把「镜像解析 → 层叠语义 → 体积账 → 门禁判定」串起来的可复用库。

## 项目方向与适用场景

- **CI 体积门禁**：把「镜像不超过 200MB」「禁止把 `node_modules` 打进镜像」写成规则，命中即失败，流水线直接红。
- **镜像体检报告**：一次跑出体积、浪费、跨层重复写入、热点目录，输出 text / JSON / HTML / CI 注解四种格式。
- **逐层审计**：`--layer N` / `--path P` 看第 N 层应用后的文件树与该层 diff；`--tui` 提供全屏交互式看树。
- **镜像获取与保存**：`--from-image` 走本地 docker/podman/nerdctl，`--from-registry` 直连 registry 拉取并落成 docker-archive tar 或 OCI layout，全程不碰 daemon。
- **教学与研究**：whiteout 语义、层间 diff、efficiency 口径都以文档 + 可运行测试固定下来，适合作为镜像格式的 MoonBit 参考实现。

## 拟实现的核心功能（本次申报周期内的新增与深化）

1. **补齐门禁表达能力**：规则 DSL 现支持 `maxImageSize` / `maxLayerSize` / `maxWastedSize` /
   `minEfficiency` / `denyPaths` / `allowPaths` / `maxFileSize`；继续补「按层追溯违规来源」与
   基线与增量对比（只对本次变更的体积负责，避免 base image 背锅）。
2. **分析口径可解释化**：把 `wasted` 的两种口径（`cumulative - min` 与 `overwritten + deleted`）、
   efficiency 的分母剔除策略写进 API 文档与报告字段说明，并补上跨实现对照测试。
3. **镜像来源闭环**：`registry_cli` 增加鉴权覆盖面（Bearer / Basic / 匿名）与错误重试、
   校验 digest 与 size 一致性，支持直接从远端出报告而不落盘。
4. **TUI 收尾**：补过滤与抽文件（原版 `Ctrl+F` / `Ctrl+E` 的对应物）、大镜像下的视口与渲染性能；
   让 TUI 与 CLI 报告共享同一批数字，不出现两个口径。
5. **可复用性打磨**：每包稳定 API 边界与 `.mbti` 约定、错误类型统一、可运行示例进 README，
   各包 README 的示例代码纳入测试（现已用 `moonbit check` 代码块方式实现）。

## 技术路线

- **依赖单向分层**：`oci_spec`（纯类型层，无外部依赖）→ `layer_tree` → `image_analysis` → `image_ci`；
  `docker_cli` / `registry_cli` / `tui` 挂在链路外侧，离线分析链不反向依赖它们。
- **生态去重**：tar、gzip/zstd、sha256、JSON 复用 MoonBit 生态已有实现（`moonbitlang/x`、`moonbitlang/async`），
  只自研生态空白且是本项目贡献点的部分：whiteout 语义、层叠 diff、efficiency 口径、规则 DSL、终端宽度表。
- **可测试性优先**：所有镜像构造走 `build_tar` 之类的手工夹具，不依赖网络与 docker；
  真实 fixture 放 `oci_spec/fixtures`，快照测试记录树与报告输出。
- **平台约束显式化**：仅 native 可用的包（`docker_cli` / `registry_cli` / `tui`）标
  `supported_targets = "-all+native"`，其余保持 wasm 可编译，避免模块级 target 冲突。
- **质量闸门**：`moon fmt --check`、`moon info` 后 git diff 断言（防止 `.mbti` 漂移）、
  `--deny-warn`、覆盖率报告，全部由一份 `scripts/ci.sh` 驱动，GitHub 与 CNB 不漂移。

## 移植或参考说明

- 原项目名称：dive（wagoodman/dive）
- 原项目链接：https://github.com/wagoodman/dive
- 原项目许可证：MIT
- 本项目许可证：Apache-2.0

与原项目相比，本项目做了以下重新设计：

- 定位为**库优先**：dive（Go）是一体化 TUI 应用，本项目把镜像解析、层叠树、体积分析、门禁拆成可独立复用的 MoonBit 包，
  TUI 只是其中一层视图。
- 不移植 docker/cli、docker/docker、gocui 等 Go 生态依赖；镜像获取改为两种 MoonBit 侧实现：
  进程内封装 CLI 后端 + 直连 unix socket 的 Engine 后端，以及**原版没有的** registry 直连拉取（不依赖本地 docker）。
- 门禁部分在原版 `maxImageSize` / `maxLayerSize` / `maxWastedSize` / `minEfficiency` 之外，
  补齐路径白/黑名单与单文件上限，规则以 MoonBit 数据结构表达、从 JSON 加载。
- 术语与口径差异（如 `wasted` 的两种算法、efficiency 分母是否剔除 base image）逐条写进文档，
  并在 JSON 报告中同时给出两套字段，便于与原版对照。

## 附录：常用命令

```bash
# 体积体检 + 门禁
dive demo-image.tar --rules rules.json --format annotations

# 逐层审计 / 效率表
dive demo-image.tar --layer 1 --path /app
dive demo-image.tar --efficiency --top 20 --format json

# 在线镜像与远端 registry
dive nginx:latest --from-image --tui
dive --from-registry library/nginx:1.27
dive --save --from-registry --archive-format oci -o ./nginx-oci ghcr.io/owner/repo:tag
```
